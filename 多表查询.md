## 非自连接





### 等值连接

如果列名在多个表中同时存在，需要“表名.列名”来注明

```sql
SELECT e.last_name,e.salary,d.department_name,e.department_id
FROM employees AS e,departments AS d
WHERE e.department_id = d.department_id;
```

这是“等值连接”

这一步，说白了，就是找到一个外键，当两表外键相等时，说明这条信息就是同一个人的





*   主键：指的是标识表中的唯一的一条记录的，保证数据不会重复（确定一条数据）

*   外键：通过那个字段和其他的表取得链接的（连接两个表）







 注意：如果from后面已经给表起了别名，那么在查询的字段中、在where条件过滤的字段中只能使用别名来替代表名

（就是from里面的表名用了别名，其他地方的表名都得换上别名）





### 非等值连接

查找员工的薪资属于另一个表的什么等级

```sql
SELECT last_name,salary,job_grades.grade_level
from employees,job_grades
WHERE employees.salary >= job_grades.lowest_sal && employees.salary <= job_grades.highest_sal;

想找到自己的薪资所匹配的等级，那自己的薪资肯定在这个等级的范围之内
笛卡尔积把所有可能性列出来
做一个条件匹配，只要自己的薪资大于等于本等级最小并且小于等于本等级最大，这条薪资就处于自己所在的等级内，输出就行了
```

这是“非等值连接”









## 自连接



在员工表中查找员工id、员工姓名、以及主管的id、主管的姓名（主管id就是指的前面的员工id，员工可以是下面员工的主管）

## 内连接





*   内连接：

```
SELECT e.last_name,e.salary,d.department_name,e.department_id
FROM employees AS e,departments AS d
WHERE e.department_id = d.department_id;
```

这种就是内连接，只输出匹配上的数据





```
SELECT e.last_name,e.salary,d.department_name,e.department_id
FROM employees AS e
INNER JOIN departments AS d ON e.department_id = d.department_id;
```

新版本写法（INNER可以省略）





格式：

`SELECT 字段名`

`FROM 表明`

`JOIN  表名1  ON 链接条件1；`

`JOIN  表名2  ON 链接条件2；`







## 左外连接

```
SELECT e.last_name,e.salary,d.department_name,e.department_id
FROM employees AS e,departments AS d
WHERE e.department_id(+) = d.department_id;
```

左外连接不仅会输出内连接的数据，还会保留左表的全部行，即便没有匹配上右表合适的数据，所以右表空缺的位置会直接放上NULL

（在这场匹配中，左表的行数和数据绝对不会少）

>   注意：sql99以后已经不支持此种写法了，换下面的写法





```
SELECT e.last_name,e.salary,d.department_name,e.department_id
FROM employees AS e
LEFT JOIN departments AS d ON e.department_id = d.department_id;
```

LEFT表示左外连接











## 右外连接

```
SELECT e.last_name,e.salary,d.department_name,e.department_id
FROM employees AS e
RIGHT JOIN departments AS d ON e.department_id = d.department_id;
```

右外连接不仅会输出内连接的数据，还会保留右表的全部行，即便没有匹配上左表合适的数据，所以左表空缺的位置会直接放上NULL

（在这场匹配中，右表的行数和数据绝对不会少）

















## 多表联立





```
SELECT e.employee_id,l.city,d.department_name
FROM employees e
LEFT JOIN departments d ON e.department_id = d.department_id
LEFT JOIN locations l ON d.location_id = l.location_id;
```

这是三表联立



------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------

可能有人会说，要是四表联立，五表联立，他们所联立的列名并不全是一张表的上的列名怎么办

（就是一表数据为AB，二表数据为BC，三表数据为CD）

```sql
SELECT ...
FROM 1
JOIN 2 ON 1.B = 2.B
JOIN 3 ON 2.C = 3.C
```

可以看到，ON的后面并不一定和JOIN后面这张表产生关联



ON 后面是一个**布尔表达式**，它可以引用**当前查询里已经出现过的任意表**，不限于 JOIN 紧跟的那张。只要引用的表在前面出现过（FROM 或之前的 JOIN 里），就合法。

## 联合查询 UNION





联合查询：UNION

合并左右两边select的结果之后，进行去重


 

```
SELECT 1,2,3
UNION
SELECT employee_id,department_id,last_name
FROM employees;
```

注意：UNION联合查询左右两边SELECT的列数必须一致，否则会报错





>   UNION去重，返回出来
>
>   UNION ALL  不去重



```
SELECT 1,2,3
UNION ALL
SELECT 1,2,3;
```

## 满外连接

就是输出的表中，既有左外连接和右外连接，又有内连接的数据





```sql
SELECT employee_id,last_name,department_name
FROM employees e 
LEFT JOIN departments d ON e.department_id = d.department_id
WHERE d.department_id IS NULL
UNION ALL #没有去重操作，效率高
SELECT employee_id,last_name,department_name
FROM employees e 
RIGHT JOIN departments d ON e.department_id = d.department_id;
```

上下两种写法都行，上面的写法是“单左”加“中和右”不去重，下面的写法是“单左”和“单右”然后进行去重

```sql
SELECT employee_id,last_name,department_name
FROM employees e 
LEFT JOIN departments d ON e.department_id = d.department_id
UNION
SELECT employee_id,last_name,department_name
FROM employees e 
RIGHT JOIN departments d ON e.department_id = d.department_id;
```
